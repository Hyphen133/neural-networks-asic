MNIST on a 1×1 Tile

A 784→16→10 digit classifier in 0.031 mm² of silicon. It holds no weights and no image — the host streams one pixel-and-weight byte per clock, and the chip keeps a single 20-bit accumulator.

01 — The constraint

A 1×1 tile is 31 318 µm², and weights don't fit in it

The IHP TinyTapeout 1×1 tile measures 202.08 × 154.98 µm. At the sg13g2 row height of 3.78 µm that is exactly 41 standard-cell rows. OpenLane places at 60 % density by default, so the working budget is roughly 18 800 µm² of cells.

A 784→16 layer has 12 544 weights. At 4 bits each that is 6.2 kB. A flip-flop in this library (sg13g2_dfrbpq_1) costs 48.99 µm², so storing those weights on chip would need about 2 460 000 µm² — 78 whole tiles for the weights alone, before a single gate of arithmetic.

So the design question is not "how do we compress the network" but "what must actually live on the die". The answer turns out to be: the partial sums, and nothing else.

02 — Two decisions

Stream the weights, and pick the loop order that needs one accumulator

The host owns the weights. Every clock it presents one byte: the high nibble is a 4-bit pixel, the low nibble is a 4-bit signed weight. Eight bits in, one multiply-accumulate out — the pin bandwidth and the compute rate are exactly matched, with no buffering on either side.

The loop order is the second decision, and it is the one that saves the area. The obvious schedule streams pixels on the outside: read pixel 0, apply it to all 16 hidden neurons, move on. That needs 16 live accumulators. Inverting the loops — every pixel for hidden unit 0, then every pixel for unit 1 — leaves exactly one sum alive at a time. The host sends the same 12 544 bytes either way.

Everything else follows from those two choices. Only the winning class and its score are kept, so there is no ten-element score vector. Biases are shifted in through the accumulator itself, so there is no separate bias register or load path. ReLU costs nothing because the clamp that produces a 4-bit activation already discards negatives.

03 — Datapath

One multiplier, one adder, one accumulator, used four ways

The accumulator serves the first layer, the second layer, and the bias load. The multiplier's activation input is a two-way mux: the incoming pixel nibble during layer 1, a hidden register during layer 2. That single mux is the whole difference between the two layers.

Requantisation between the layers is a wire shift and a clamp — never a multiply by a floating-point scale: 

hidden[n] = acc < 0 ? 0
          : min(15, acc >> shift1)

Twenty bits is the worst-case-safe width for any int4 weight set: 784 × 15 × 8 = 94 080 needs 18 bits, and the loadable bias needs headroom above that. The trained model only ever reaches 5 118, which is where the ACC_W = 16 option in section 08 comes from — it is safe for this weight set, and the sticky overflow flag on uo_out[6] is what guards the assumption if you retrain.

05 — Host interface

One byte per clock, and the host may stall whenever it likes

uio[0] is in_valid, uio[1] is is_cmd. A byte is consumed on any rising edge where in_valid is high. There is no backpressure to honour — the chip always keeps up — so a host that can only manage one byte every ten cycles simply runs ten times slower, with no protocol change.

12 838 clocks at 50 MHz is 257 µs per image, or 3 895 images per second. Layer 2 is 160 of those bytes; the first layer is 97.7 % of the work, which is exactly the ratio you would expect from 12 544 versus 160 multiply-accumulates.

06 — Training

The training forward pass is the hardware

The usual failure mode for a quantised accelerator is a model that scores 96 % in the framework and 89 % in silicon, because the rounding, scaling and saturation semantics drifted apart somewhere between the two. The way to not have that problem is to not have two sets of semantics.

Training runs custom straight-through estimators rather than a quantisation library. Brevitas and TorchAO both pick their own floating-point scales, which you then have to reverse-engineer into a shift; here the forward pass literally executes clamp(floor(acc / 2^s), 0, 15) on integer weights, so the exported values need no conversion step at all. Three estimators cover it:

  • Weights — clamp(round(w), −8, 7) forward, clipped pass-through backward, with the latent float weight clamped after each step.
  • Activations — clamp(floor(acc / 2^s), 0, 15) forward, gradient 1/2^s gated to the representable band.
  • Biases — parameterised in output units so their gradients have sane magnitude, then rounded into accumulator units.

A learnable logit temperature keeps cross-entropy well conditioned against scores in the hundreds. It divides all ten logits equally, so it cannot change the argmax and it costs nothing in silicon.

The requantisation shift is calibrated once from the 99th percentile of the layer-1 pre-activations at initialisation, then frozen: 6 for the int4 models, 4 for ternary. Sixty epochs takes about a minute on a CPU.

The 4-bit activation range is genuinely the bottleneck

In the trained HIDDEN = 16 model, 38.5 % of hidden activations read zero and 17.3 % saturate at 15. The available range is fully used in both directions, which is what you want from QAT — and it also says plainly where the remaining accuracy went. Widening activations to 5 bits, not adding neurons, is the next thing to try if 95.5 % is not enough.

08 — What measurement changed

Two things the plan got wrong

Ternary weights are not the win

The original plan assumed a ternary {−1, 0, +1} datapath would be the big area saving, because it removes the multiplier entirely. It was built, tested and measured. It saves 491 µm², or 3.1 %.

The multiplier was never the cost. A 4×4 signed multiply is a few dozen gates; the area is in flip-flops, the hidden register file's muxing, and the variable barrel shifter. Meanwhile ternary costs 2.7 accuracy points at the same width.

Same width, HIDDEN = 16
95.47 % vs 92.76 %

W4A4 wins outright

For 491 µm² more — 3.1 % of the design — you get 2.7 accuracy points. Keep the multiplier.

Equal accuracy
15 688 vs 20 803 µm²

Ternary needs 32 neurons to catch up

Ternary at HIDDEN = 32 reaches 95.55 % — a statistical tie — using 25 % more area.

The cheap savings are elsewhere. Hard-wiring the requantisation shift (SHIFT_FIXED=6) deletes the 20-bit barrel shifter for −1 092 µm². Narrowing the accumulator to 16 bits, which the measured value range in section 04 permits, saves another 1 133 µm². Together they take the shipping configuration from 50.1 % to 43.5 % utilisation at identical accuracy. Both are verified in simulation against the same image-by-image comparison. The price is flexibility: a hard-wired shift means you cannot retune it after tape-out, and a 16-bit accumulator is only worst-case-safe if you keep the weight distribution you trained.

It is not fast, and that was never the point

On the same laptop that trained it, PyTorch runs one image through the equivalent float network in 7.6 µs on a single CPU thread — 34× faster than the chip, and batched it is three orders of magnitude faster still. Anyone comparing wall-clock times will conclude the ASIC is pointless.

The honest framing is that the comparison is not speed, it is what the silicon costs. This is 0.031 mm² on a shared shuttle, running one multiply-accumulate per clock at 50 MHz because that is what an 8-bit host port delivers — the datapath is interface-bound, not compute-bound. Widen the port or clock it faster and the same design scales linearly, with no change to the architecture.

09 — Scaling limits

Where this stops working, and why it isn't the obvious place

MNIST makes the design look like it scales by making the network bigger. It does not. There are three ceilings, and they bind in an order that catches people out — the one that decides what is actually possible has nothing to do with how much silicon is left, and nothing to do with the 4-bit arithmetic either.

Ceiling 1 — persistent activation state

The only thing the chip must hold is activations that outlive a layer. Pushing HIDDEN past the shipped configuration shows exactly where that runs out.

Ceiling 2 — the design throws away every bit of weight reuse

This is the ceiling that actually decides what is possible, and it is not an area limit at all. Because the chip stores no weights, every multiply-accumulate needs a fresh weight nibble off the pins. For a dense layer each weight is used exactly once per image, so streaming wastes nothing — that is precisely why MNIST works so well here. A convolution reuses each kernel weight at every spatial position, and this architecture re-sends all of them.

Ceiling 3 — eight input pins is one MAC per clock

Four bits of activation plus four bits of weight fills the dedicated input port exactly. Repurposing the six spare uio bits as inputs gets you to about 1.75 MACs per clock and no further. The datapath is interface-bound, not compute-bound — which is also why every latency in the table above is simply the MAC count divided by 50 MHz.

The escape hatch: stop storing activations at all

Ceiling 1 only exists because the hidden layer lives on chip. Add one opcode that streams the accumulator back out as nibbles — READ_ACC — and the host holds every activation instead. The chip stops being a two-layer MLP and becomes a general streaming dot-product engine that can serve any topology, convolutions included.

It was prototyped and synthesised to cost the claim rather than guess it: 262 µm², 1.7 %. It is not in the shipped RTL — the MNIST design does not need it — but the measurements say what it would buy.

At 25 % utilisation the state ceiling is gone entirely and three quarters of the tile is free. What remains is ceiling 2 and ceiling 3, which no amount of spare area fixes: the free space would buy roughly 220 flip-flops of weight cache — about 900 bits — against convolutions that want to reuse kernels tens of thousands of times.

Measured: what CIFAR-10 actually gives you

Rather than assume, the same arithmetic was trained on CIFAR-10 — identical estimators, identical requantisation, only the input width changed from 784 greyscale values to 3072 RGB ones. The 20-bit accumulator still holds: 3072 × 15 × 8 = 368 640 stays inside ±524 287, asserted throughout the run.

The quantisation is not what is costing you. A float network of the identical topology, given the same training budget, lands at 41.11 % — below the 4-bit version. That float figure is a deliberately unoptimised baseline, not a ceiling; well-tuned float MLPs on CIFAR-10 reach the mid-fifties. But the direction of the result is unambiguous either way: dropping to W4A4 costs roughly nothing here, and doubling the hidden layer buys two points while pushing the design off the tile.

A small convolutional network reaches about 90 % on the same data. The 45-point gap is topology, not precision — which is exactly why ceiling 2 is the one that matters. Making the arithmetic more accurate cannot help; only convolution can, and convolution is what this architecture cannot afford.

The niche, stated plainly

This architecture suits networks with no weight reuse and few persistent activations — which means dense layers on small inputs. The moment convolution enters, the property that makes the design fit on a 1×1 tile, holding no weights at all, is exactly the property that makes it slow. Scaling up is not a matter of adding neurons; it is a different architecture with a weight cache, and a weight cache does not fit.

10 — Verification

Four models, three equivalences, no floating point after training

Each link in the chain is checked mechanically, and each one catches a different class of bug.

Five cocotb tests run against both RTL and, once a netlist exists, gates:

  • Reset state, including that uio_oe leaves the two handshake pins as inputs
  • The three-byte bias path and clamp(acc >> s, 0, 15), including saturation at both ends
  • A hand-computed MAC and argmax, small enough to check on paper
  • Real MNIST images end to end — every hidden activation and the predicted class compared against the golden model
  • A stalled stream, proving idle cycles are inert

All five pass for HIDDEN = 8, 16 and 32, for the ternary datapath, and for both area trims. The RTL lints clean under verilator -Wall across every one of those parameter combinations.

11 — Tape-out

Dropping this into ttihp-verilog-template

  1. Copy tt_um_mnist_nn.sv into src/, delete the template's project.v, and point source_files: at the SystemVerilog file.
  2. Copy info.yaml, docs/info.md and test/ over the template's, and fill in author and Discord handle.
  3. Add numpy to test/requirements.txt — the testbench imports the golden model.
  4. The template's test.yaml and gds.yaml workflows then run unmodified; tiles: "1x1" is already set.

The train/ and artifacts/ directories are not consumed by the GDS flow. Keep them for reproducibility or strip them; neither affects the hardened result.

Before you submit

Run ./area_check.sh after any RTL change — it re-synthesises against the real liberty and prints utilisation, which is the number that decides whether the design fits. Then run the cocotb suite for the exact parameter set you are hardening, not just the default. Every configuration in the results table has been through both.

Open questions worth a second silicon run: 5-bit activations instead of more neurons; a wider host port to break the one-MAC-per-clock ceiling; and folding the bias into the first few streamed MACs to delete the bias path entirely.
